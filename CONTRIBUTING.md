# Правила роботи з репозиторієм

## Гілки

Створюйте гілку від актуального `main`:

- `feature/BIM-XX-short-name` — нова функція;
- `fix/BIM-XX-short-name` — виправлення;
- `docs/BIM-XX-short-name` — документація.

## Коміти

Використовуйте Conventional Commits і додавайте номер Jira-задачі:

```text
feat(web): додано форму завантаження (BIM-62)
fix(api): виправлено перевірку токена (BIM-47)
docs(repo): уточнено локальний запуск (BIM-61)
```

## Pull Request

1. Перед відкриттям PR підтягніть актуальний `main`: `git pull --rebase origin main`.
2. Запустіть `npm run lint`, `npm run typecheck`, `npm run test` і `npm run build`.
3. Додайте до PR посилання на Jira-задачу, короткий опис та спосіб перевірки.
4. Отримайте review й дочекайтеся зеленого CI.
5. Зливайте через **Squash and merge**, щоб одна задача залишала один коміт у `main`.

## Захист `main`

Для `main` потрібно ввімкнути:

- заборону прямого push і force-push;
- щонайменше одне схвалення PR;
- обов'язкове проходження CI;
- актуальність гілки перед злиттям.

## Безпека

Не додавайте до Git:

- `.env` і реальні ключі;
- клієнтські DWG/DXF;
- платні тексти ДБН/ДСТУ;
- тимчасові файли та результати локальної обробки.
