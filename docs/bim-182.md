# BIM-182 — зони та евакуаційні виходи

База: origin/dev `3ef7714`, 25.11.2026. Jira BIM-182, BIM-73, BIM-75,
BIM-76, BIM-131, BIM-107, BIM-129 та BIM-170 прочитані через Atlassian MCP.
Попередніх PR BIM-182/BIM-122 пошук GitHub не знайшов. AGENTS.md не знайдено.

## Аудит

У dev вже були BIM-73 (`6f99462`), BIM-75 (`266972f`), BIM-76 (`3ef7714`),
редактор BIM-164/BIM-80, таблиця BIM-72, камера/оверлей BIM-60 та стабільний
переглядач BIM-121. Міграції 010_room_zones, 013_exits та наступні міграції
проходів присутні; їх застосування у розгорнутій БД не перевірялося.

Зони/виходи мають моделі Pydantic біля API-модулів, а не у спільній JSON Schema.
Клієнтські типи відтворюють ці моделі; контракт сервера не змінено.

## Реалізація і файли

- `plan-features-api.ts`: авторизовані GET/POST/PATCH/DELETE через apiFetch,
  обробка HTTP-помилок, перевірка списку відповіді.
- `use-plan-editor.ts`, `plan-edit-overlay.tsx`, `plan-editor-panel.tsx`:
  зони й виходи в наявному редакторі, чернетка, вершини/стрілки, висота,
  скасування, спільний lock запитів і reconciliation після неоднозначної помилки.
- `plan-features-panel.tsx`: вибрана кімната, створення/редагування/видалення зон,
  автоматичні/ручні виходи, порожній стан, loading/error/retry.
- `drawing-detail.tsx`, `drawing-viewer.tsx`, `drawing-canvas.tsx`,
  `drawing-overlay.tsx`, CSS: спільне завантаження даних, межі/висоти зон,
  виходи у WCS через ту саму камеру без повторного завантаження DXF.
- `rooms-table.tsx`, `types/rooms.ts`: висоти зон у рядку батьківської кімнати;
  зонована кімната не вимагає вигаданої загальної висоти перед /place.
- `plan-features*.test.*`: API, чернетки, валідація, помилки, повторні кліки,
  скасування, виходи, зв'язок зон із кімнатою та блокування розміщення.
  Старі тести циклу process/place ізолюють новий API окремим mock.

## API

Префікс `/api/v1`: GET `/drawings/{id}/zones`, POST `/rooms/{id}/zones`,
PATCH/DELETE `/zones/{id}`; GET/POST `/drawings/{id}/exits`, DELETE `/exits/{id}`.
Для виходу немає PATCH: редагування через прибирання та нове позначення.
Зони додаються багатокутниками по одній, залишаючись частинами кімнати.
Висота null дозволена сервером; інтерфейс явно пояснює недостатність даних.
Складні контури, допуски входження й перекриття перевіряє BIM-73;
клієнт перевіряє виродження/самоперетини й діапазон (0, 100].

## Перевірки

- Початкова база: lint, typecheck, 330 web + 91 contracts пройшли.
- Після змін: lint, typecheck, 339 web + 91 contracts пройшли.
- API: 404 unittest пройшли (реальні FastAPI/parser/placement, mock DB/Storage).
  PowerShell повернув ненульовий exit через stderr; звіт unittest: `Ran 404 ... OK`.
- Production build: компіляція, типи й генерація сторінок успішні, але команда
  завершується `SecurityFatalError` з рекомендацією оновити встановлений Next.js.
  Це відтворюється на базі до змін; захист не обходився, залежності не змінено.
- Компонентні UI-тести пройшли. Браузерну WebGL-перевірку не виконано:
  `npm run dev --workspace @bim/web -- --port 3130` зупиняється тим самим
  SecurityFatalError. Наскрізні тести проти реальної БД не запускалися.

## Критерії та обмеження

| Критерій | Стан |
| --- | --- |
| Вибір кімнати, багатокутні зони, окремі висоти | Реалізовано |
| Зони належать одній кімнаті, збереження/скасування | Реалізовано; API та hook-тести |
| Геометрія, висота, помилки, повторні кліки | Клієнт + чинна серверна валідація; тести |
| Межі/висоти на плані, дані в таблиці | Реалізовано |
| Автоматичні виходи EXITS/«Вихід» | Чинний backend → GET → оверлей |
| Ручні виходи, повідомлення без виходів, повторний GET | Реалізовано |
| BIM-170 та точна відповідність BIM-131/BIM-129 | Не підтверджено |
| Наскрізний тест розгорнутого API/БД, merge | Не виконано |

У репозиторії знайдені старі fixtures Дениса та синтетичні API-тести; комплект
BIM-170 з таблицею очікуваного не знайдено, у Jira немає вкладень/посилання.
Figma MCP відсутній; вебзапит не відкрив файл, браузерний host недоступний.
Візуальні рішення спираються на локальні tokens/docs, потребують звірки макета.

Серверні мутації зон/виходів не інвалідують попередній DXF результату. UI просить
повторити розміщення; після повторного відкриття сервер не віддає ознаку його
застарілості. Це обмеження BIM-73/BIM-75, алгоритми та API тут не змінено.

Ручна перевірка: у тестовому середовищі створити дві неперекривні зони з різними
висотами, спробувати перетин/вихід за контур; скасувати чернетку; перевірити
EXITS і «Вихід», додати ручний вихід, перезавантажити сторінку; повторити /place
й перевірити DXF. Перевірити масштабування, клавіатуру й вузький екран.
