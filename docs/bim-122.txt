BIM-122 - Device overlay and rule provenance
Base: origin/dev 3ef7714. Branch: feature/BIM-122-device-overlay.

Implemented
- Existing WCS/camera overlay reused for smoke, heat, manual call points and sounders.
- Original user-supplied BIM-107 SVG assets replace handwritten symbol approximations.
- Plan and legend share the same source assets; compact Ukrainian labels and live counts.
- Room-state legend uses original exports. Unknown device types retain a visible fallback.
- Optional Device.ruleId forwarded from stored devices.rule_id in drawing GET and device mutation responses.
- Existing GET /api/v1/rules resolves the exact id. verified is the only verified state;
  needs_review and needs_verification show review; absent, unmatched, pending or future status stays unknown.
- Review/unknown indicators and accessible labels/tooltips are distinct from violations.
- Rules reload with drawing result revisions after processing/placement; API failure shows retry and unknown state.
- Selected-room border and device/vertex editor geometry adjusted to supplied reference variants.
- Shared drawing frame uses the exported 1440px/40px/1036px/24px/300px layout, original logo and self-hosted Inter.
- Room/device modes, per-type layer checkboxes, zoom percentage, in-plan controls and right-hand details replace the generic toolbar/editor stack.
- Modal deletion uses the existing accessible dialog. Save/cancel and processing locks retain their existing API behavior.
- No placement algorithm, migration, auth policy or production database changes.

Already existed
- Four contract device types, BIM-75 manual placement, BIM-76 sounder placement, stored rule_id.
- Authenticated drawing/rules API adapters, camera projection and keyboard editing.
- Drawing response previously discarded rule_id. The user approved this optional contract extension.
