# Архітектура монорепозиторію

## Межі модулів

- `apps/web` — Next.js інтерфейс, маршрути, форми, таблиці та DrawingViewer.
- `apps/api` — FastAPI, авторизація, робота з кресленнями та правилами. Реалізується в BIM-53.
- `packages/contracts` — єдине джерело JSON-контрактів між вебклієнтом і API.
- `docs` — архітектурні рішення, інструкції та процеси команди.

## Потік DXF

1. Вебклієнт створює запис креслення через API.
2. API повертає підписане посилання на приватне сховище.
3. Браузер завантажує DXF безпосередньо у сховище.
4. API отримує шлях до файла, читає його з тимчасового каталогу та формує результат.
5. Вебклієнт отримує структуровані `Room[]` і `Device[]` за спільним контрактом.

Файли не проходять через Next.js і не зберігаються в Git або Postgres. У базі залишаються метадані, статус і шлях у сховищі.

## Домовленості контрактів

- API повертає координати з DXF WCS без масштабування: початок `(0, 0)`, `+X` праворуч, `+Y` вгору. Перетворення для Canvas/SVG виконує вебклієнт.
- Контур кімнати логічно замкнений і не повторює першу точку наприкінці масиву. Площа передається в м², висота — у метрах або `null`.
- `from_file` використовується лише в запиті. Після читання DXF API записує `resolvedUnits` як `mm` або `m`; якщо одиниці визначити неможливо, креслення переходить у статус `error`.
- Обробка запускається через `POST /drawings/{id}/process` і виконується у фоні. Стан `ProcessingJob` перевіряється через `GET /processing-jobs/{id}`.
- `GET /drawings/{id}` повертає нове тимчасове `downloadUrl`. Підписані посилання не зберігаються в базі.
